## Treatment route

The authorized G4 route is a bounded replacement of the Session work surface behind its existing entry, followed by Q3 retirement of the verified superseded implementation. Session Terminal is explicitly retired by product decision. F-074 proves that the generated Terminal request and Runtime persistence model are root causes, so this slice uses the authorized C3/D3 ceiling for one coordinated cutover while preserving every existing Runtime row: `session_id` becomes a typed scope identity, existing rows become Session-scoped, and Project Terminal creation becomes a Project-level command that ensures a Main-Workspace Runtime. No compatibility wrapper or synthetic Session identity is retained.

### F-074 compatibility and migration

| Producer/storage | Old consumer | Current consumer | New consumer | Rollback version |
| --- | --- | --- | --- | --- |
| Old `runtimes(session_id)` | Existing server and clients | Migrated on startup | Read as `scope_kind=session, scope_id=<session>` | Checkpoint `8c8abe9` plus pre-migration data-root backup |
| New scoped Runtime rows | Unsupported | Coordinated server migration | New server/CLI/Web only | Old binary cannot read the renamed column |
| Terminal create with caller `runtime_id` | Accepted by old server | Removed in coordinated cutover | Project ID resolves/ensures Runtime server-side | Restore checkpoint and pre-migration data root |

Migration state is deliberately short because Janus is single-node and startup holds the exclusive data-root lock: append migration, preserve and classify existing rows, regenerate all in-repository consumers, run foreign-key/invariant checks, then start readiness. The migration does not delete Runtime children or manufacture Project/Session IDs; its irreversible aspect is old-binary schema incompatibility, not data loss.
