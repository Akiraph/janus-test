## Executive summary

- Current runnable state: Typecheck, lint, build, and one deterministic live browser-to-supervisor workflow pass on this host; mocked suites remain baseline evidence only until their useful assertions move to live coverage.
- Main conclusion: The generic message/Turn/SSE path works, but the Session UI still exposes unfinished command concepts while concentrating query, command, projection, layout, and secondary-view responsibilities in one component and one global stylesheet.
- Highest-priority findings: Keep the live workflow as a gate, then remove transport/UI mismatches and establish one typed timeline boundary before visual cleanup.
- Next smallest action: Refactor the Session projection and component boundaries while preserving the now-proven live path.

| F-036 | High | Confirmed | Open | Tool requests and results are not part of reconstructed model history. | `execute_turn` keeps Tool messages only in its local `chat` vector; `run_one_tool` persists the Tool Call row and timeline projection but no `tool_result_ref` message, while `load_chat_history` reads only message text. `ChatMessage` cannot represent the assistant response's declared Tool Calls for either Provider adapter. | A resumed Turn loses the result it was waiting on, and a subsequent real Provider request can receive a Tool result without the required preceding assistant Tool declaration, so Job/Ask recovery and multi-Round tool use are not protocol-stable. | Extend the provider-neutral message contract with declared Tool Calls, atomically persist accepted declarations with the Round, persist bounded Tool results as context messages, and reconstruct both from durable history before every resumed Round. |

| F-039 | Medium | Confirmed | Open | Turn usage is overwritten by only the latest resumed execution segment. | `execute_turn` resets `total_in` and `total_out` to zero on every invocation and `complete_turn` writes those values over the Turn totals; Ask, Job, and model recovery create additional persisted Rounds before the final invocation. | Session/model usage projections undercount resumed work and cannot be reconciled with the durable Round ledger. | Derive terminal Turn usage from all accepted Round rows in the settlement transaction instead of carrying invocation-local counters. |
| F-040 | Medium | Confirmed | Open | Turn completion summaries do not satisfy the documented stable shape. | Text-only model completion synthesizes only `summary`, `main_changes`, and `risks`; the `finish` tool accepts the same three fields, while `SES-TURN-03` also requires executed verification, unexecuted verification, and remaining risk. | The primary completion UI and later context cannot distinguish verified work from unverified claims, especially after real-environment testing was made the acceptance standard. | Define one typed completion summary shape at the Supervisor boundary, require it from `finish`, and use an explicit conservative fallback for text-only model stops. |
